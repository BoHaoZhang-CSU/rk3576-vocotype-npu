# 生态调研：这件事有没有人做过

调研时间：2026-09-30。方法：GitHub 搜索 + 上游仓库 issue/README 排查。

> **先声明结论的性质。** 下面的「没有找到」是**搜索快照**，不等于不存在。
> GitHub 搜索有分词和索引限制，中文项目尤其容易漏。所以这里给的是
> 「公开可检索的范围内没有被占据」这个较弱的结论，以及据此判断的**贡献价值**。

---

## 1. 直接搜索的结果

| 搜索 | 结果 |
|---|---|
| `vocotype` + `npu` | 0 |
| `vocotype` + `rknn` | 0 |
| `fcitx5` + `rknn` | 0 |
| `fcitx5` + NPU 语音输入 | 没有成品项目 |

**「RKNN ASR → fcitx5 输入法」这条端到端路径没有被占据。** 各个零件都有，
但没人把它们串成「在 Linux 输入法里按一个键，NPU 跑离线识别，文字进光标处」。

## 2. 上游 VocoType 的状况

- **零个 NPU 相关 issue。** 说明没有人在推动这个方向。
- 上游的定位是**「纯 CPU」**，README 里把 CPU 推理当作卖点之一
  （不需要独显、不需要额外硬件）。
- 这意味着 NPU 支持**不是**上游的路线图内容 —— 别指望他们主动做。

## 3. 上游对下游项目的态度

上游 README 里的外链目前只有自己的官网 / release / 文档，以及**祖先**项目
`233stone/vocotype-cli` —— **没有找到下游项目链接的先例**。

所以「往上游 README 加链接」这条路**没有先例可循**，成功率未知。
但它代价极低（一个 issue 的事），仍然值得试。

## 4. 各零件各自的现状

| 零件 | 现状 |
|---|---|
| sherpa-onnx 的 RKNN 后端 | 官方维护，有 rk3576 的离线 Paraformer 现成模型 |
| RKNN 上的 ASR | 有各种 demo，但都是「命令行跑一段 wav」级别 |
| fcitx5 输入法框架 | 成熟，插件机制完善 |
| VocoType | worker 是独立进程，天然可替换（这是本项目的切入点） |

**缺的从来不是零件，是那条线。**

---

## 5. 所以这个工作的价值在哪

按「别人能直接拿走什么」排：

1. **一个能用的成品。** 别人不用重新踩 B1（PyPI wheel 不带 RKNN）、
   C1（VAD 切分丢字）、D1（NPU 内存共享池）这些坑。
2. **「CPU 时间降到 1/140」这个数据。** 大家谈 NPU 加速都谈墙钟，
   但对一个跑桌面环境的开发板，**把 CPU 让出来**才是真收益。
   这个视角在 RK3576 的公开材料里很少见。
3. **一组可复现的踩坑记录。** 尤其是 D1（NPU 内存共享池 + `exit(255)`），
   这个行为在 sherpa-onnx 和 RKNN 的文档里都没写，撞上会毫无头绪。
4. **一个接入模式。** 「不改上游、只换 worker 进程」这个做法可以复制到
   别的 VocoType-like 项目上。

## 6. 建议的贡献路径

按代价从小到大：

| 方式 | 代价 | 说明 |
|---|---|---|
| **上游 README 加一行链接** | 极低 | 上游有过先例，成功率最高 |
| 本仓库开源 + 发到 Rockchip/Radxa 社区 | 低 | 目标受众正好对口 |
| 给 sherpa-onnx 提 issue/PR 补文档 | 低 | 把「PyPI wheel 不带 RKNN」写进文档 |
| 给 VocoType 提 issue 建议支持 `worker_path` 写进文档 | 低 | 这个逃生舱口目前是**没写进文档**的 |
| 往上游提 PR 加 NPU 支持 | 高 | 跟上游「纯 CPU」定位冲突，不建议 |

**最值得做的一件事**：给 VocoType 提个 issue，建议把
「worker 可以用 `asr.worker_path` 换掉」写进文档。这是**对上游本身也有利**的
改进（他们的代码已经支持了，只是没人知道），而且完全不需要他们改一行代码。
本项目正好是这个逃生舱口的第一个真实用例。

---

## 7. 不要做的事

- **别把 VocoType 说成自己的项目。** 它是
  [LeonardNJU](https://github.com/LeonardNJU/VocoType-linux) 的，
  血缘上来自 [233stone/vocotype-cli](https://github.com/233stone/vocotype-cli)。
  本项目只是一个外挂 worker。
- **别宣称「比 CPU 快 140 倍」。** 墙钟是 5～12 倍，1/140 是 **CPU 时间**
  的比值，两个是不同的东西。混着说会被人抓。
- **别在 RK3588 上宣称可用。** 理论上行（换 rk3588 版模型），但没实测过。
