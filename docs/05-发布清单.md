## 3. 提交前必须决定的：`dist/*.whl` 怎么办

那个 15 MB 的预编译轮子是**别人能不能「直接就用」的关键**（省 25 分钟编译），
但不该进 git 历史 —— **一旦提交，就永远留在历史里了**，仓库会一直背着这 15 MB。

三个选择：

| 方案 | 说明 |
|---|---|
| **A. 传到 GitHub Release（推荐，采用这个）** | 仓库干净，别人从 Release 下。`install.sh` 同时支持本地路径和 URL |
| B. 不管，就这样 | 收到代码的人得自己编。README 里给了完整配方 |
| C. 直接提交进仓库 | 能用，但仓库 +15 MB 且不可撤销。**不建议** |

已经在 `.gitignore` 里排除了 `dist/*.whl`，所以默认走方案 A/B。
`dist/README.md` **会**被提交（它是说明文档，不是二进制）。

**方案 A 的具体操作**：建好仓库、`git push` 之后，在 GitHub 上
Releases → Draft a new release → tag 填 `v1.0.0` → 把
`dist/sherpa_onnx-1.13.8-1-cp311-cp311-manylinux_2_27_aarch64.whl`
拖进附件框 → Publish。

发布后这个地址就能直接用了（`install.sh` 会自己下载并缓存到
`~/.cache/vocotype-npu/`）：

```
VOCOTYPE_NPU_WHEEL=https://github.com/<用户名>/vocotype-npu/releases/download/v1.0.0/sherpa_onnx-1.13.8-1-cp311-cp311-manylinux_2_27_aarch64.whl ./install.sh
```

## 5.5 怎么把这个包发给别人

⚠️ **别直接打包整个目录。** 目录有 157 MB，其中 141 MB 是 `.venv/`
（本机环境，对别人没用，而且是机器相关的）。真正的「作品」只有 **440 KB**。

| 方式 | 怎么做 | 适合 |
|---|---|---|
| **A. 发 GitHub（推荐）** | `git push` 上去 | 别人 `git clone` + 跑 `install.sh` |
| B. 传压缩包 | 先删 `.venv/`，再 `zip -r vocotype-npu.zip vocotype-npu -x 'vocotype-npu/.venv/*'` | 私下发给一两个人 |
| C. 连环境一起给 | 整个目录拷过去 | **不建议** —— venv 里的绝对路径在别人机器上是错的 |

不管哪种方式，**模型（1.0 GB）都不在包里**，别人跑 `install.sh` 时自己下。

**`dist/` 里那个 15 MB 的轮子要一起给** —— 那是别人省 25 分钟编译的关键：

- 走方式 A 的话，把它传成 Release 附件（见第 3 节），别人一条命令就能拿：
  `VOCOTYPE_NPU_WHEEL=<Release 的 URL> ./install.sh`
- 走方式 B 的话，把 `.whl` 跟压缩包一起发，让对方放进 `dist/` 目录，
  `install.sh` 会自己发现它。

轮子的校验和（方便别人核对）：

```
d11e8e985a546e8f6cb6af2026a617ac180e920882333692b887798edbb73280  sherpa_onnx-1.13.8-1-cp311-cp311-manylinux_2_27_aarch64.whl
```

### 已经实跑验证过的

- **`./install.sh` 全流程，从一个空的假 HOME 开始，跑到底 `exit 0`**
  （2026-09-30）：下轮子 → 装轮子 → **从 GitHub 下三个模型（真的下了 1.0 GB）
  并解压** → 装启动器 → 生成 `npu.json` → 改 `config.json`（含备份）→
  **用刚下下来的模型跑冒烟识别，认出正确中文** → 重启服务。
  这条路是别人拿到包之后要走的**同一条路**，等于替他们先走了一遍。
- `./install.sh --check`（在本机跑，输出和实际状态一致）
- `./install.sh --revert`（用假 HOME 测的：正确删掉 `worker_path`，
  保留 `idle_timeout_s` 和无关的键，生成备份）
- 轮子从 **URL** 装（起个本地 http 服务当源测的，下完还会缓存到
  `~/.cache/vocotype-npu/`）
- `dist/` 里那个轮子：**干净 venv** 装进去 → 启动 worker → 识别出带标点的正确文字
- 启动器按 VocoType 的真实调法被调用（连那个没用的 `--asr-model-dir` 也正确忽略）
- `ONLY=cpu` / `ONLY=npu` 两种单跑模式都实跑过
- 补丁 `git apply --check -R` 通过（说明线上源码确实是打过补丁的状态）

### 还没验证的（别当成已经验过）

- **F9「按一下切换」的实机手感** —— 需要有人真的按键试。编译和加载都确认了
  （`vocotype.so` 已加载），但交互行为没法在无头环境里试
  （当时屏幕是锁的，没往里注入按键）。

  「换一块 RK3576 板子也这样」。
- **RK3588 等其它平台** —— 模型和轮子都是按平台分的，换平台要换对应版本。
