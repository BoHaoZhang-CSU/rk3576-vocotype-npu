## 3. 提交前必须决定的：`dist/*.whl` 怎么办

那个 15 MB 的预编译轮子是**别人能不能「直接就用」的关键**（省 25 分钟编译），
但不该进 git 历史 —— **一旦提交，就永远留在历史里了**，仓库会一直背着这 15 MB。

三个选择：

| 方案 | 说明 |
|---|---|
| **A. 传到 GitHub Release（推荐）** | 仓库干净，别人从 Release 下载。`install.sh` 已经支持 `VOCOTYPE_NPU_WHEEL=<路径>` |
| B. 不管，就这样 | 收到代码的人得自己编。README 里给了完整配方 |
| C. 直接提交进仓库 | 能用，但仓库 +15 MB 且不可撤销。**不建议** |

已经在 `.gitignore` 里排除了 `dist/*.whl`，所以默认走方案 A/B。
`dist/README.md` **会**被提交（它是说明文档，不是二进制）。

## 5. 首次提交怎么做

```bash
cd /path/to/vocotype-npu
git init -b main
git add .
git status          # 确认没有 .venv/ models/ dist/*.whl 混进去
git commit -m "NPU 加速版 VocoType 离线 ASR worker（RK3576）"
```

**提交前务必看一眼 `git status`。** 确认这三样没被加进去：
`.venv/`、`dist/*.whl`、任何 `npu.json`。

⚠️ **提交者身份现在是个占位符**（`radxa <radxa@localhost>`）。
发布前换成你自己的：

```bash
git config user.name "你的名字"
git config user.email "你的邮箱"
# 把已有的两个 commit 的作者也改掉
git rebase --root --exec 'git commit --amend --no-edit --reset-author'
```

## 5.5 怎么把这个包发给别人

⚠️ **别直接打包整个目录。** 目录有 157 MB，其中 141 MB 是 `.venv/`
（本机环境，对别人没用，而且是机器相关的）。真正的「作品」只有 **440 KB**。

| 方式 | 怎么做 | 适合 |
|---|---|---|
| **A. 发 GitHub（推荐）** | `git push` 上去 | 别人 `git clone` + 跑 `install.sh` |
| B. 传压缩包 | 先删 `.venv/`，再 `zip -r vocotype-npu.zip vocotype-npu -x 'vocotype-npu/.venv/*'` | 私下发给一两个人 |
| C. 连环境一起给 | 整个目录拷过去 | **不建议** —— venv 里的绝对路径在别人机器上是错的 |

不管哪种方式，**模型（1.0 GB）都不在包里**，别人跑 `install.sh` 时自己下。
`dist/` 里那个 15 MB 的轮子**要一起给** —— 那是别人省 25 分钟编译的关键。

轮子的校验和（方便别人核对）：

```
d11e8e985a546e8f6cb6af2026a617ac180e920882333692b887798edbb73280  sherpa_onnx-1.13.8-1-cp311-cp311-manylinux_2_27_aarch64.whl
```

### 还没验证的（别当成已经验过）

- **模型下载那条路（1.0 GB）没真跑过。** 本机模型早就在别的目录里，走的是
  「已有，跳过」分支。三个 URL 都用 HTTP HEAD 确认过（302，合计 1013 MB），
  但**完整的下载 + 解压没跑过一次**。
- **改 VocoType 配置那一步**是在 `--no-config` 之外的单独测试里验的，
  不是跟安装流程一起跑的。
- **F9「按一下切换」的实机手感** —— 需要有人真的按键试。编译和加载都确认了
  （`vocotype.so` 已加载），但交互行为没法在无头环境里试
  （当时屏幕是锁的，没往里注入按键）。
